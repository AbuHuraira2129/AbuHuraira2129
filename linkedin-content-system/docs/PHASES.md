So once a draft is pushed to Buffer with `mode: "addToQueue"`, it *will* auto-publish at the channel's next queue slot with no further tap — you were asked and explicitly chose this over the safer `saveToDraft: true` alternative (which sits in Buffer's Drafts until you manually queue it). The human gate for Buffer-published content is therefore your approval *before* pushing to Buffer (Notion status flip, or direct chat confirmation), not a second gate inside Buffer itself. `generated_content.buffer_post_id` tracks the link. Currently done interactively via the Buffer MCP connector (it authenticates via this session's OAuth, not a portable API token) rather than a headless script — see SETUP.md if you want a scriptable/cron path later, which needs a personal access token from https://publish.buffer.com/settings/api. |

## Decisions made when this was built

- **Positioning goal changes**: the system *can* suggest a reposition (via `analyze:voice`), but it only ever inserts a row with `status='suggested'` plus a Notion review task — nothing flips to `status='active'` without you doing it (SQL update or a future small approval script).
- **Connection notes**: fully custom per prospect, not templated per ICP segment. Costs one Claude call per prospect in `draft:connection-note`.
- **Profile improvement**: monthly `review:profile` job compares your latest snapshot against the active goal + latest voice analysis and files findings as a Notion task. No auto-edits to your profile, obviously — LinkedIn profile fields aren't writable via API anyway.

## What's intentionally never automated

Nothing here scrapes LinkedIn, drives a headless browser against linkedin.com, or auto-connects/auto-messages on your behalf. Connection notes and prospecting stay fully manual-execute (Phase 4) — nothing there ever reaches Buffer or any posting API. For posts, there are two paths: land in the Notion approval queue for manual copy-paste (the original design, still the default), or — once you approve a draft — get pushed to Buffer, which *will* auto-publish it at the next queue slot (see Phase 2b for why: LinkedIn doesn't support Buffer's manual-approve mode). Buffer is LinkedIn's own official, ToS-compliant API partner, not scraping/automation-detection risk — but be aware the gate moved: your approval has to happen *before* pushing to Buffer, not after.
